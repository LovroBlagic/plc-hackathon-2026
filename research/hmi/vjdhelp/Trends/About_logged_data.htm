13.1.1 Working with Data Logging

Data logging provides you with the capability to collect, store, and view sampled data for a variable. With data logging, you need to determine:

  • What variables you want to record data for

  • When data should be collected

  • Where to store your data

  • How data can be displayed

  • Displaying multiple variables in a single CSV file

When you determine the data collection and storage options for a data logging group, you are essentially defining the options for an individual variable that is assigned to that data logging group. For more information, see Section 13.2, Setting Up a Variable for Data Logging.

For data logging purposes, you must set up the Time Zone and Time Adjustment (Daylight Saving Time) on the target machine properly before downloading an application. If you change the date or time on the target machine instead of using the Time Zone and Time Adjustment settings after the application has been running and historical data has been logged, then this historical data will no longer be valid with the new date and time. For example, if Time Adjustment is mistakenly disabled in a location where Daylight Saving Time is used when an application is downloaded to the target machine, and Time Adjustment is later enabled in run time, the time may become off by one hour as the time will automatically be adjusted for Daylight Saving Time. Manually changing the time by one hour to compensate will then cause problems between previously logged data and new data. In this example, if you change the time back 1 hour, then there might be two sets of data for the same time. Or, if you change the time forward 1 hour, the time when historical data is flushed from memory may occur 1 hour late, resulting in a 1-hour gap in the data logging.

For information on setting the Time Zone and Time Adjustment (Daylight Saving Time), see Section 4.5.3, Displaying Data Using Time Zone and Configuring Daylight Saving Time.

If you must manually change the date or time, remove previous historical data for the current day from the application. To do this:

  • Flush the data to the storage device. See Section 18.9.1.6, Variable Methods: flushToStorage.

  • If required, extract and back up the data. See Section 20.5.2, Transferring and Converting Data Using the Data Manager.

13.1.1.1 Determining What Data to Log

In working with data logging, you must first determine what variables need to be logged. The variables that you choose are elements in the production process specific to your site. You may need to collect data for the purposes of figuring out volume, speed, or units produced over a period of time. You may need to collect data about certain elements on a production line to comply with company or regional guidelines.

After you determine which variables need to be logged, you would assign the variable to a data logging group. A data logging group contains a set of properties that specifies the data collection method and data storage details for a variable. You would create a logging group from the Data Logging node in the Navigator window.

To assign a variable to a logging group, you can either make a selection in the Logging Group property of the Variable Properties dialog box or define the Logging Group property in the Variable Property Inspector.
