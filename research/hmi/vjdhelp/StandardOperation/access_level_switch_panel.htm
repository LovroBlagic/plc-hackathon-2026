Defining Security Levels for Security Groups

Parts, panels, function keys, and popup windows can be assigned a security level value so only authorized security groups can access them. Vijeo-Designer provides two types of Security Modes: Level Based and Bitmask Based.

When a user logs onto a target, the user's security level value is stored in the system variable _UserLevel. For more information on system variables, see Section 6.7, System Variables.

Defining Security Levels

Target Security must be enabled before you can define Security Levels for the security groups, see Section 4.8.7, Security Settings.

To define a security level value for a Security Group:

  • In the Security Editor, click the group's Security Level cell and type in a value.

 

Level Based Security

For Level Based Security, to access a secured Part, panel, function key, or popup window, the security group must have a security level value that is equal to or greater than the security level value assigned to the Part, panel, or popup window.

The following scenario shows how Level Based security works. In this scenario, Security Mode is set to Level Based and a Switch is assigned with a security level of 10.

Bitmask Based Security

For Bitmask Based Security, to determine if a security group has access to a secured Part, panel, function key, or popup window, Runtime performs a bitwise AND operation using the binary value of the security group's security level and the binary value of the secured object's security level. If the result of the bitwise AND operation is true, the security group has access to the secured object. If the result is false, the security group is denied access. For information about bitwise AND operations, see Section 18.3.5, Operators: Bit Operators.
