4.8 Setting up Security Protection for Targets and Projects

Vijeo Designer's security features protect projects, panels, parts, Data Manager, and other areas from unauthorized users accessing them. Users must log in with the proper user name and/or password to access secured areas. Users can access different areas, depending on their security level. For more information, see Defining Security Levels for Security Groups. When setting up security, you can customize your login method. For more information, see Section 4.8.4, Runtime Security Operations.  

The following is a list of security features managed by the Security node:

  • Target Security
    Prevents an unauthorized user from logging in to a target and from accessing secured panels, popup windows, function keys, and parts on target machines. See Section 4.8.2.1, Protecting Panels and Switches from Unauthorized Users.

  • Download Security
    Prevents an unauthorized user from downloading projects to a secured target machine. Secured targets require users to enter in their user name and password in order for download and installation to proceed. See Section 4.8.2.2, Protecting Targets from Unauthorized Project Downloads.

  • Data Manager Security
    Prevents an unauthorized user from using the Command Line or the Data Manager to transfer run-time data to and from the target machine. See Section 4.8.2.3, Protecting Targets from Unauthorized Data Transfer.

  • Web Gate / Web Server Security
    Prevents an unauthorized user from using Web Gate to access a target machine. See Section 4.8.2.4, Protecting Web Server/Web Gate Connections from Unauthorized Users.

  • Security Data (Common Security)
    By default, projects are set up so you manage a different list of security groups and security users for each target machine. Common Security is a feature that you can use to share security groups and users among a group of target machines, so you configure your users one time and at run time update your user list one time. See Section 4.8.6, Common Security.

The following lists the security feature managed by the project node.

  • Project Password
    Prevents an unauthorized user from opening a protected project. See Section 4.8.8, Adding Project Security.
