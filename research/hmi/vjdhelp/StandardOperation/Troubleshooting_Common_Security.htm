4.8.6.3 Troubleshooting Common Security

The following are some issues you may encounter at run time when working with Common Security.

  • Cannot run secured operations because Security Server is unavailable

  • Deleted users are still running secured operations

Cannot run secured operations because Security Server is unavailable

There may be a number of reasons why the Security Server is unavailable. For example, the target machine may be offline due to maintenance requirements, the system administrator may be re-configuring the network, or the target machine may be damaged. Without the security server, operations on client target machines may not be possible.

The following procedure describes how to update the user application running on the target machine so that it can work with a different security server. The following steps work only if in the Project properties you enabled Download User and defined a user name and password. For Project properties, see Section 4.3.2, Creating a New Project.

  1. From the Navigator window's Project tab, select the Project node and view its properties.

  2. Expand the Use Common Security node to view the Security Server property and select a target machine. This unit must be online for panel operators to run secured operations on the target machine.

  3. Download the project to all targets in the project.

Deleted users are still running secured operations

In the following scenarios, an unauthorized user may be logged in to a target machine.

User remains logged in

  1. The panel operator logs in to a target machine that is set up with common security.

  2. Delete the operator's security user name and password from the common security settings.

  3. The panel operator continues to run secured operations.

Solution:

  • In the Security properties, you can set up the Inactivity Time-Out to automatically log out the user if the target machine is not in use.

Security Server is offline

In the Project properties, Cache Users is set to Yes.

  1. The panel operator logs in to a target machine that is set up with common security.

  2. The target machine confirms the login information with the security server.

  3. The target machine caches the security information.

  4. The panel operator logs off.

  5. Remove the panel operator's user name and password from the common security settings.

  6. The security server goes offline.

  7. The panel operator logs in. Log in is successful.

Solution:

  • After changing the common security settings, erase the cache by restarting the target machines that is set up with common security.

  • You can also prevent log in when the security server is offline. In the Project properties, set Cache Users to No.

  • In the Security properties, you can expire passwords after a defined number of days.
