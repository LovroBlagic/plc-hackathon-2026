9.4.2 Actions Wizard

When you create an action or panel action, a wizard takes you through each step needed to create the action or panel action. You can create up to 100 actions.

The steps in the wizard are detailed below.

  1. To start the wizard, in the Navigator, right-click Actions and select New Action, or right-click Panel Actions and select New Action.

  2. From the Trigger Type drop-down list, select one of the following:

Trigger Type

Description

Periodic

Runs the action on a periodic basis as configured in the trigger settings.

Scheduled

Runs the action according to the schedule in the trigger settings. This trigger type is available only for Actions.

Conditional

Runs the action depending on whether or not certain conditions are met as set in the trigger settings.

Event

Runs the action when an event occurs on the target as configured in the trigger settings.

Variable Alarm

Runs the action when the variable's alarm status changes.

Alarm Group/Category

Runs the action when the selected Alarm Group or Alarm Category's active alarm count changes from 0 or returns to 0 as configured in the trigger settings.

 

  1. Once you have selected the trigger, the corresponding trigger settings are displayed:

  2. Trigger Type

    Setting

    Description

    Periodic

    Frequency

    Frequency is defined in seconds, with a range from 0.1 to 86400.0 seconds (1 day). You can also enter the time in milliseconds, minutes, and hours by typing the time unit (ms, m, h). Time units are not case-sensitive. The entered value is converted to the number of seconds.

    For example, type 1h and the property converts the value to 3600.0.

    Type 1m and the property converts the value to 60.0.

    • Depending on the operation and communication load at runtime, the action may not repeat exactly as defined in the frequency.

    • When using an external variable for Bit, Word, and String operations with a very small frequency (for example, 1 second), the action may execute before the PLC has fully initiated. Therefore, the external variable may not be updated properly when the Action is first triggered, causing unexpected results.

    Scheduling

    Monitors action and checks if they are running at the configured frequency.

    Depending on the selected Scheduling option, when the CPU is under heavy load and the action is delayed, you can alert users to the delayed action with extra runtime messages (Monitor), pause the action and run it when the CPU is available (Low), or choose not to run any extra operations (Normal).

    • No matter which Scheduling option you choose, if the action is delayed by more than 5 seconds, the following warning message displays, "High CPU usage. Periodic actions –which may be user or system created– are not running."

    Select Monitored, Normal, or Low.

    • Monitored. If the action does not run at the defined frequency, the following message displays to the user: Monitored periodic action is running but slower than defined.
      Another Monitor message displays to the user when the action begins running at its defined frequency again: Monitored periodic action is now running at the defined rate.
      In addition to these messages, the High CPU usage message also displays if the action is delayed for 5 or more seconds.

    • Normal. Only displays the High CPU usage message if the action is delayed for 5 or more seconds.

    • Low. If the action is delayed, the action skips one run before attempting to run again. If the action is delayed for 5 or more seconds, displays the High CPU usage message.

    PublishTo

    Define the publish settings for the action. Select whether the action is published to the target machine (HMI Runtime), Web Gate (Web Gate), or both (All). For more information, see Section 23.2.4.1, Web Gate Publish Settings.

    Enable Interlock

    Actions run when the condition defined in the Enable Interlock field is true.

    For more information, see Section 9.6, Using Interlock to Prevent Accidental Touch Inputs.

    Scheduled - Daily

    Creates a schedule for the action to run on a daily basis.

    Sync Time (HH:MM)

    Enter the time of day that the action runs. The time is tracked with the clock on the HMI and the PC system clock for Web Gate.

    Repeat Every

    Type a number in the first field and then select Minutes or Hours in the drop-down list. For example, if you want the action to recur every four hours, type 4 in the first field and then select Hours from the drop-down list.

    Publish To

    See Publish To above.

    Enable Interlock

    See Enable Interlock above.

    Scheduled - Weekly

    Creates a schedule for the action to run on a weekly basis.

    Time (HH:MM)

    Enter the time of day that you want the action to start on the target. The time is tracked with the clock on the HMI and the PC system clock for Web Gate.

    Days of the Week

    Select the days that you want the action to run.

    Conditional

    Publish To

    See Publish To above.

    Enable Interlock

    See Enable Interlock above.

    Trigger Variable

    The variable controls when the action occurs. For more information on variables, see Section 6, Variables.

    Trigger Condition

    The Trigger Variable is evaluated using the condition selected here. When the condition is met, the action is run. Select one of the following conditions:

    • When True. Whenever the Trigger Variable changes from 0 to any value, the action is run once.

    • On Data Change. Whenever the Trigger Variable changes in value, the action is run once.

    • When False. When the Trigger Variable changes to 0 from any value, the action is run once.

    • Do not use external variables with a Conditional Action triggered at startup. The Action executes before the PLC fully initiates, so the values of the external variables may not be updated before the Action is triggered, causing unexpected results.

    Event

    Publish To

    See Publish To above.

    Enable Interlock

    See Enable Interlock above.

    Trigger Event

    Defines how the action is triggered. Select one of the following triggers:

    • On Startup. Available only for Actions. The action runs once when the Vijeo-Designer application starts.
      If you have a panel action set up on the initial panel with an On Open trigger, that panel action runs before the On Startup action.

    • Do not use external variables with On Startup. The action executes before the PLC fully initiates, so the values of the external variables may not be updated before the Action is triggered, causing unexpected results.

    • On Shutdown. Available only for Actions. The action runs once the Vijeo-Designer application shuts down.

    • On Open. Available only for Panel Actions. The action runs when the panel is displayed at Runtime.

    • On Close. Available only for Panel Actions. The action runs when the panel is closed.

    • On Low Space. Available only for Actions. The action runs when the HMI is low on the CF Card/SD Card. You must set the Low Space Notification property in the Target properties. For more information, see Section 4.5.1.4, Options. Note that this option is not available for Web Gate.

    • When Touch Panel. Available only for Actions. The action runs whenever the panel is touched. If touch operations are set up on switches or drawings and that object is touched, the action's When Touch Panel script runs first and then the touch operation runs.

    Variable Alarm

    Variable

    Defines the variable's alarm state that triggers the action. For Select one of the following triggers:

     

    • When alarm is active - The action runs whenever the variable's alarm becomes active. For example, when using Limit Alarms and the variable enters the Lo alarm state, the alarm action is triggered. If the alarm condition changes, for example, from Lo to LoLo, the alarm action is triggered again. For more information on Limit Alarms, see Section 16.3.3, Word Alarms.

    • When alarm is acknowledge - The action runs whenever the alarm is acknowledged.

    • When alarm returns to normal - The action runs when whenever the alarm returns to normal.

    • Any state change - The action runs whenever the variable's alarm changes state.

    Alarm Group/Category

    Alarm Group/Category

    Defines the alarm group or alarm category whose active alarm count triggers the action. For more information on alarm active count, see section 16.2.4.1, Alarm Group Settings: Counters. Select one of the following triggers:

    • When active count greater than 0 - The action runs once the specified alarm group's active alarm count becomes greater than 0. The action only runs once when the active alarm count becomes greater than 0.

    • When active count returns to 0 - The action runs once the specified alarm group's active alarm count returns to 0.

     

  3. Click Next.

  4. Use the following options to configure the Trigger Settings:

Trigger Setting

Description

Description

A description name to identify your action. It is displayed in the Actions column in the Actions Editor or in the Panel Actions Editor.

If you do not enter a description name, the Actions column displays the operation.

Operation

Select one of the following types of operations. The Operation settings depend on the type of operation you select and the type of operations your target supports. For a list of all the operations, see Section 9.5, Operations. For more information on creating multiple operations for one action, see Section 9.5.19, Setting Up Multiple Operations.

  1. Once you have set all the options, click Finish.
