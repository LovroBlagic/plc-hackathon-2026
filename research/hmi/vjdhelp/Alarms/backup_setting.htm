16.2.3 Setting up the Alarms and Events Node

In the Alarms and Events node, you can set configurations for:

  • Backing up alarms to a target machine's SRAM

  • Clearing the Print and Save control variables after printing or saving

  • Printing selected alarm and event groups and alarm categories in real time

  • Setting an alarm group or an alarm category to output to the DIO ALM pin (Alarm pin)

  • Setting the Alarm behavior for acknowledging alarms

Right-click the Alarms and Events node in the Navigator window's Project tab, and select Properties to display the Alarms and Events properties in the Property Inspector.

The following table lists the properties for the Alarms and Events node.

Property

Description

Backup Alarm Group

This property is only for alarm groups. This function backs up the alarm messages on the target machine's SRAM so that when Runtime is shut down and restarted, the alarm messages still display in the alarm summary.

  • When set to Yes, the alarm messages are backed up.

  • When set to No, the alarm messages are cleared when Runtime shuts down.

Each target machine has different amounts of SRAM available. When you use this alarm backup feature, it limits the number of alarms you can set up for each alarm group.

Print/Save Clear Option

Use this field to set up how the print or save variable's value is cleared once the alarm message is printed or saved.

See Sections 16.3.5.4, Clear Option When Printing and 16.3.6.6 Clear Option When Saving.

Real-time Printing

Enable to print alarm messages whenever alarms change state between Active, Acknowledged, Not Acknowledged, or Return to Normal. See Section 16.3.5.2, Configuring Real-Time Printing.

Alarm output on DIOPort.Sys1

This property is only for alarm groups. This function sets the selected alarm group or alarm category to output to the DIO ALM pin.

  • When an alarm in the specified alarm group or alarm category becomes active, the DIO ALM pin turns on.

  • When all the alarms in the specified alarm group or alarm category become Returned to Normal (RTN), Acknowledged (ACK), or Not Acknowledged (UNACK), the DIO ALM pin turns Off.

See Section 24.6, DIO Ports for information about the DIO port.

Track Users in Alarms

This feature records the user name of the operator who acknowledged the alarm and displays it in the User Name column in the alarm summary. If this feature is disabled, the User Name column displays nothing. For more information on the User Name column, see Section 16.2.6.3, Columns Tab.

 

To track users in a data sharing scenario, all targets must have Track Users in Alarms enabled. Unexpected results occur when this feature is not enabled for all data sharing targets. For example, if the client is tracking but the server is not tracking, the server does not record user names associated with alarm operations. In another example, if the server is tracking but the client is not tracking, the server does not receive any user names from the client to record. For more information on alarm data sharing, see Section 22.1, Sharing Data Between Tablets, Smartphones, and Target Machines and Section 16.3.1.4, Remote Categories.

 

  • Events always record user names and display them in the User Name column in the event summary.

E-mail Attachment

Click the ellipsis to open the E-mail Attachment dialog box. In the dialog box, you can configure the format of alarm records that will be embedded in the outgoing e-mail.

Bring Runtime to Front

This property is only for alarm groups. Targets that use the Windows operating system can have other windows open besides the Vijeo-Designer Runtime, which may be minimized or hidden by another window. This function brings the Runtime window on top when an alarm is triggered. For a list of targets that support this feature, see Appendix 5, Hardware Specifications.

Bring Runtime to Front supports the following settings:

  • Disabled: No action is taken when an alarm is triggered.

  • Any Alarm: The Vijeo-Designer Runtime window is brought to the top when an alarm is triggered. Other windows open on the target machine remain unaffected.

  • An alarm group or alarm category: The Vijeo-Designer Runtime window is brought to the top when an alarm in that alarm group or alarm category is triggered. Other windows open on the target machine remain unaffected.

Show System Error Window

This setting gives you the option to turn system error message windows on or off. The system error message window displays error messages for runtime errors that occur, such as PLC communication timeouts or insufficient space on the CF Card/SD Card. If you are using a small-sized target, you may want to use this feature to turn off the system error message window, because it takes up a lot of space on the panel.

Select Yes to show system error message windows on the panel at runtime. If you select No, the panel will hide the windows.

This property does not affect the generation or logging of system error messages, which can still be viewed using event summaries and the system error log viewer.

  • The Show System Error Window setting does not control the system error window in the Offline Configuration menu.
