16.3.5.5 Printing Limitations

When you are printing alarm and event messages, please note the information below.

Printer

  • When printing by page, enter a page break after printing all the number of lines on one page.

  • If an error occurs on the printer side (e.g. printer busy, not online), print data is stored in a buffer until the error is resolved. If the printer error is not resolved after 2 or 3 minutes, a runtime error message will display; however, printing will successfully continue once the error is resolved.

  • If the target machine turns OFF in the middle of printing, printing does not continue after the power is restored.

Real-Time Printing

  • Always prints in Log format.

  • Alarm Group, AlarmCurCount, AlarmSumCount, and Title will not be printed.

  • You cannot specify a language for Real-Time printing. Real-Time printing will print in the user's default language.

Batch Printing

  • The maximum number of alarms and events you can print using Batch printing is defined in the Property Inspector for the Alarm Group (Num of History Alarms property and Num of Log Alarms property) and Event Group (Total Records property).

When there are more alarms and events than the set maximum, the target machine removes the oldest alarms and events to make room for the newest alarm and event information.

  • When printing an alarm category with multiple alarm groups and event groups, do not use the same variable for the Print Control Variable, the Status Variable, and the Error Variable. If you set up the same variables, the Alarm Category, Alarm Groups, and Event Groups will print out duplicate copies.

  • Alarm groups, event groups, or alarm categories using the same Print Control Variables, the Status Variables, and the Error Variables, print in their creation order. For example, alarmgroup1 was created before alarmcategory2, so alarmgroup1 will print first.
