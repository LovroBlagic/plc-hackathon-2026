Remote Category Key Points

The section explains special remote category behavior.

  • Remote categories do not behave exactly the same as normal alarm/event categories.

Alarm Summary Remote Operation Support

The following operations are available for Alarm summaries displaying a remote alarm or event group with read/write sharing.

  • ACK current alarm

  • ACK all alarms

  • Delete selected Alarm

  • Delete all alarms

  • Clear selected Alarm

  • Clear all Alarms

Remote Alarm Script Support

The following script methods can be executed from a client target on alarm and event groups with read/write sharing:

  • Alarm and Event Summary Script Methods

  • delete

  • deleteAll

  • Alarm Group Script Methods

  • ackAll

  • addMessage

  • clearSum

The following script methods only affect the alarm summary on the target that ran the script. For example, if the script runs on the server target, the client target’s alarm summary is unaffected.

  • Alarm Summary Script Methods

  • moveTop

  • moveBottom

  • PageUp

  • PageDown

  • jumpTo

  • showSubDisplay

Time stamps

Alarms are time stamped with the server target’s system time. Time stamps are the number of seconds from the Unix epoch time (January 1st 1970, 0:00:00). The client and server target interpret the time stamp according to their time zone settings. For example, an alarm triggered at 6pm on an east coast server target (Eastern Standard Time) displays as 3pm on the west coast client target (Pacific Standard Time). If the client and server target’s times are out of sync, time stamps will show incorrect dates and times. For more information on time zones, see Section 6.7.2, Using Date and Time System Variables.

Recording User Names for Alarm Actions

When Track Users in Alarms is enabled on both client and server target machines, the user name of the operator deleting or acknowledging an alarm is recorded and displayed in the alarm summary. This user name will be visible from both the client’s and server’s alarm summary.  

Actions Not Supported by the Client Target

Actions that you created on the server target will not execute on the client target. If you are creating a system that will run on a client target, make sure you design a system that does not use actions.
