7. Project Optimization

If a user application's memory requirements are nearing the memory limits for the target machine, application performance can deteriorate. For good performance, you should allocate a buffer of 10% to 20% of memory and disk space—more if you plan to upgrade the application in the future. To test your application's SRAM and DRAM memory requirements, see Section 25.3.3, Checking Memory Usage.

Here are a few ways you can reduce the memory requirements for your project.

  • Delete unused variables

  • Use indirect addresses and delete duplicate panels or popup window panels

  • Reduce the size of large bitmaps

  • Use the exact same image object for bitmaps

  • Use Text Block Display for large text files

  • Reduce the number of alarms stored in memory

  • Optimize memory usage in scripts

  • Reduce the color depth of bitmaps

  • Limit the duration and frequency of video recordings at runtime

Delete unused variables

Objects that are not required by the application occupy valuable space in memory. The most-often abused object is the variable.

To delete unused variables:

  1. Validate or build the user application.

  2. In the Variable Editor, click the Filter Icon, point to Filter by, and select Unreferenced Variables.

  3. Delete these variables.

Use indirect addresses and delete duplicate panels or popup window panels

You can use indirect addresses if the user application is set up with:

  • Multiple panels or popup window panels with the exact same parts and drawings—only the PLC device addresses are different between panels.

  • PLC device addresses that are consecutive or follow a pattern.

On a single panel, set up parts with external variables that use an indirect address, and define an offset value of 0. By simply changing the value of the offset you can display a whole different set of device addresses. For more information on indirect addressing, see Section 6.3.3, Dynamically Referencing Device Addresses.

This method allows you to reduce the number of panels, popup window panels, and the number of variables in your application.

Reduce the size of large bitmaps

You can save valuable memory space by reducing the size and number of bitmap images in your application.

If you are using bitmaps as a background to cover the whole panel or a large portion of the panel, you should use one of the drawing tools (rectangle, ellipse, and so on) available in Vijeo-Designer. To make sure the object color matches the background color in the bitmap, see Section 7.3.1.2, Copying Colors on your PC.

If the bitmap includes a section that contains an image and the rest is a background, then you should replace the bitmap with two objects: a smaller bitmap with only the image, placed on top of a rectangle for the background.

Use the exact same image object for bitmaps

When you use the same bitmap image in multiple locations, the dimensions of the image objects drawn on the panel should be exactly the same in each instance. Even though the image object may be referencing the same bitmap, if the width or height of the image object varies by even a single pixel, Vijeo-Designer will generate a different bitmap.

Wherever possible, use the Copy and Paste commands to make sure you use the exact same image throughout your project.

Use Text Block Display for large text files

There are two Toolchest parts for displaying text files:

  • Text Display

  • Text Block Display

When working with large text files, you should use the Text Block Display. The main difference with the Text Display is that the Text Display loads the entire text file into memory when it needs to be displayed, and a Text Block Display loads only the block currently displayed.

When a text file is large, such as 500KB, then the Text Display becomes cumbersome and slow to use. Whereas, the Text Block Display consumes only the memory required to display a single block within the text file.

  • When you change from a text display to a text block display, you may have to change the format of your original text file. See Section 11.7.3.1, Setting Up a Text Block Display.

Reduce the number of alarms stored in memory

Each alarm group has two properties (Num Of History Alarms and Num Of Log Alarms) that define how many history and log alarms to store in memory.

You can reduce this value to reduce the amount of memory required by your application.

Optimize memory usage in scripts

Java primitive arrays

Do not create Java primitive arrays that occupy huge amounts of space in memory.

For example, if you write the following script, a lot of space in memory will become occupied and could cause Vijeo-Designer Runtime to halt operations.

int a[] = new int[30000]; // Allocates 120K in DRAM
String or StringBuffer objects

String and StringBuffer objects are character arrays. Similar to other Java arrays, be careful when using them.

  • Vijeo-Designer takes advantage of Java's String and StringBuffer classes. When using these objects, use the same memory optimization techniques as you would with any Java program.

Script frequency and how memory is used

When the application includes periodic scripts with a fast frequency rate (less than 1 second), consider whether the script needs to run that fast. If possible, reduce the frequency of scripts.

In addition to its frequency, be careful on how much memory is allocated inside the script.

Reduce the color depth of bitmaps

When working with XBTGT Series target machines that support color, you can use graphical application tools to reduce the color depth of images to 256 colors. If the image is more than 256 colors, then 2 bytes are used to store color information for each pixel. If the image is 256 colors or less, then 8 bytes are used to store color information.

If color depth is not required in your application, then you can save some minor amounts of memory by reducing the number of colors in your images.

Limit the duration and frequency of video recordings at runtime

When working with XBTGT Series target machines that support the Video feature, limit the duration and frequency of your video recordings. Recording long videos too frequently, for example longer than 20 seconds recorded every 40 seconds, results in the target machine's high CPU usage and causes poor performance. As the number of recorded videos increases, the target machine's performance diminishes, which may affect other operations.

To avoid performance issues, reduce or limit the number of videos you store in the storage device and reduce the length of videos you record at runtime. You should always validate the performance of your runtime applications when using the Video feature and use the recommendations above as you see fit.
