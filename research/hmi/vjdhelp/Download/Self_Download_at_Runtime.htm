25.6.9.1 Self Download at Run Time

After triggering the Self Download operation:

  1. The run time retrieves the Self Download files from the FTP server and stores them in the specified local destination drive.

  2. During download, the target machine generates one CRC32 checksum for application files and another one for system files (if included). The CRC32 checksum values state the success of the Self Download operation.

  3. If the download fails, the run time aborts the Self Download operation.

After triggering the Install operation, the target machine:

  1. Confirms that the Self Download is successful and complete.  

  2. Restarts and deletes all the existing user application files and folders.

  3. Copies the newly downloaded files to the appropriate locations and deletes the Self Download folder.

  4. Restarts and runs the newly installed user application files.

  • When triggering the Self Download operation, the target machine temporarily stores both the old and new user application and system files on the local drive until the Install operation is complete. Make sure that the target machine has enough free space for this operation. To find out the amount of memory available on the target machine, see Section 26.4.6, Displaying Memory.

  • The Self Download operation aborts if:

    • The target machine type in the current project does not match with that of the update project.

    • The run time version does not match and the runtime update is not included.

    • There is not enough free space on main/secondary/optional drive.

    • Another Self Download operation is active.
