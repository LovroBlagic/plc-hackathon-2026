6.3.3 Dynamically Referencing Device Addresses

When the application uses any device address within a consecutive range, you can use indirect addresses. Using indirect addresses lets you change the device address associated with a variable, at runtime, by simply changing the value of the offset.

Indirect addresses comprise a base variable and an offset variable.

Base Variable: A base variable is an external I/O variable—its device address defines the base address, or start point. To set up an indirect address for the base variable, select the Indirect Address check box. You will then need to select an offset variable.

Offset Variable: An offset variable is an internal or external integer variable. Its value defines the offset from the base variable. The offset variable determines the number of units to shift and locates the actual device address. You cannot use another base variable as the offset variable. The offset cannot be a negative value. Do not set an offset value that's so large that is forces device addresses out of range.

Example

Base Variable
Device Address = 40001
Data Length = 16 bits

Offset Variable
Value = 5

In the above example, the variable value is 31 the value stored in device address 40006.

Offset Size

When using indirect addresses, the size of the variable determines the size of each offset. In other words, you don't have to calculate the size of your data when defining device address offsets.

Better Alternative to Arrays or Block Variables

Indirect addressing is more powerful than arrays or block variables for accessing consecutive device addresses.

Setting the elements within an array to consecutive device addresses is useful when many of the array elements are used at any one time. However, if the application calls for just one element, using an array is cumbersome. Even a single reference to an array element loads the entire array into memory. If the array contains hundreds of elements, loading the array and all its device address values could take several minutes. The array consumes too much memory to be effective.

Block variables, another method of working with consecutive device addresses, are supported only by recipes, scripts, block trend graphs, and XY graphs, and are useful only for specific needs. When you change block variable values, the equipment is not updated until you explicitly send the data. When you send or read block variable values, the entire block is either sent or received. For these reasons, the block variable is not always an optimal method for working with consecutive device addresses.

Indirect addressing is the fastest way to access one address within a range of consecutive device addresses, to minimize memory consumption, and to update data within milliseconds (see below). You can use base variables set up with indirect addresses for parts and animation. Because of the inherent lag between the time the offset value changes and the time the base variable value updates, the base variable cannot be used in scripts. If real-time indirect addressing is required in the Vijeo Designer application, please implement the indirect addressing components in the PLC application.

  • After changing the value of the offset variable, a delay occurs while the communication system updates the base variable with the device address value. The length of this delay depends on the communication load, communication medium, and the equipment. For example, with Ethernet based protocols the delay might be 100 milliseconds. Complex serial protocols could take several seconds before the base variable is updated.

  • When copying the value of an indirect variable to another internal or external variable, ensure that its value has been updated properly before performing the operation. If the value is not confirmed to be updated, the value calculated from the previous index will be copied to the internal or external variable. For example, to verify that the value of the indirect variable has been updated, a On Data Change action script can be used. The trigger variable would be the indirect variable itself, and the script would perform the copy operation. In this situation, the copy operation would only occur when the value of the indirect variable changes.
