5.3 Collecting Driver Statistics

When setting up communications with equipment such as PLCs, you can track the communication flow by viewing statistics on information such as the number of requests received, the number of responses sent, and the number of invalid messages received.

Use these statistics to optimize communications or debug your system. Driver statistics are supported by all drivers.

There are two ways to view driver statistics:

  • Configuration menu. See Section 26.5.2, Viewing Communication Statistics.

  • Variables. See Section 5.3.1, Creating Variables to Display Driver Statistics.

 Statistics

Current Statistics (@stat) and Previous Statistics (@prevstat)

The driver collects the current and previous statistics listed in the following table. In the variable's Device Address field, use @stat or @prevstat to identify whether you want to view the current statistics or previous statistics, then type a colon and the index number.

Examples:

@stat:2 = Total Count

@prevstat:8 = Initialization Failed

For details on how to set up variables so you can display driver statistics, see Section 5.3.1, Creating Variables to Display Driver Statistics.

Index

Name

Description

0

Total Good

Received without error.

1

Total Bad

The total number of errors of all types.

2

Total Count

Total Good + Total Bad.

3

No Reply

No reply was received in response to the request.

4

Checksum Failed

Received a request or response*1 with an incorrect checksum.

5

Wrong Address

Received a request or response*1 with an incorrect address.

6

Error Response

Received an error response from the equipment.

7

Invalid Response

Received a response that contained a protocol error.

8

Initialization Failed

Failed to initialize communications with the equipment.

9

Write Failed

Failed to write a new value to the equipment.

10

Internal Error

Internal driver error indicates improper driver configuration or driver failure.

11

Transmit Failed

Failed to transmit a request or response*1.

12

Unsupported Request

Received a request for an unsupported service.

13

Invalid Request

Received a request that contained a protocol error.

*1 Master-type drivers send out requests and receive responses. Slave-type drivers receive requests and send responses.

  • Driver statistics are read-only. You cannot use the Keypad to reset or change driver statistic values.

  • Driver statistics are reset to zero when you turn off the target machine or when you roll over statistics. See Section 5.3.3, Rolling Over Driver Statistics.

  • If a driver statistic variable reaches the maximum value for a 32-bit integer (2,147,483,647) and still continues to collect statistics, it will overflow to a negative number. Reset driver statistic variables before they overflow and have negative values. For example, at a rate of 100 packets per second, the Total Count counter overflows in about 248 days. To make sure the driver statistics do not overflow, you can set up a periodic script that rolls over the driver statistics and runs once a month.

  • The driver collects all the current and previous statistics listed in the above table, even if there are no variables associated with driver statistics.

System Control Words @sys

Use system control words to access information or perform operations on the driver, such as interacting with the driver statistics. The system control words use the same notation as driver statistics. e.g. @sys:3 = Roll over.

Variables that use system control words are created in the same way as driver statistics. For more details on how to set variables using system control words, see Section 5.3.1, Creating Variables to Display Driver Statistics.

Index

Name

Description

0

Last Statistic

Stores the index number of the current statistic that was last set. (Read-only)

1

State

You can write the values 1 or 0 to turn on (1) or off (0) the communication with the associated equipment. A value of 2 indicates the driver is offline for this specific equipment.

When State is 0, communication with the associated equipment has stopped.

When State is 1, there is ongoing communications with the associated equipment.

When State is 2, the driver is offline for this specific equipment. The driver has attempted to communicate with the associated equipment but has timed out for the final time.

  • Do not turn communication off with equipment if the equipment is synchronizing the target's clock. For more information on time management, see Section 24.4.4, Time Management.

  • Each equipment inside the communication driver can be enabled or disabled separately or independently.

2

Alarm

When the most recent communication packet produces an error, Alarm is 1. When the most recent communication packet is good, Alarm is 0. (Read-only)

3

Roll over

Copies the values in the current statistic variables to the previous statistic variables and resets current statistic variables to zero.

4

Testing

Vijeo-Designer can automatically test the validity of all variables for a PLC.

When the value for @sys:4 is 1, a test is currently in progress. When the value is 0, no test is in progress. (Read-only)

5

Serial Protocol

The stored value indicates the current serial protocol in use. (Read-only)

Value 0 = HWP_RS232

Value 1 = HWP_RS422_2WIRE

Value 2 = HWP_RS422_4WIRE

Value 3 = HWP_RS485_2WIRE

Value 4 = HWP_RS485_4WIRE

Value 5 = HWP_RS422_4WIRE_RTS_STATIC

Value 6 = HWP_RS422_4WIRE_RTS_TOGGLE

6

Demand Scan

When you write any value to this system control word, the communication driver forces an immediate scan of all variables on the PLC's scan list. After scanning, the scan rate for each scan group on the PLC is reset. For information on scan rates and scan groups, see Section 6.3.2.1, What is a Scan Group.

 

  • When @sys:6 is assigned to a variable, Demand Scan affects all scan groups in the associated PLC, not just the specified scan group in the variable properties.
