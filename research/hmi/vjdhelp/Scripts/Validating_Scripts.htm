18.4 Checking for Errors

You should check your scripts for errors as you write. Debugging your scripts gets more difficult if you delay this task until the end, especially if your scripts contain complex logic.

To check your script for errors, right-click inside the script editor and click Validate.

The Feedback Zone displays the results of the validation.

Double-click the error message in the Feedback Zone. The script opens up, and the pointer arrow becomes an insertion point within the line of script that generated the error. In many cases, the insertion point appears below the line of script that generated the error.

  • The editor is able to find syntax-related issues only. Issues related to programming logic may result in NullPointerException errors or other Java run time errors, but they will not display as errors in the Feedback Zone.

 

Common Scripting Errors

  • Syntax error. Indicates a problem with the formatting of your script.

  • Undeclared local variable. You may be trying to use a Vijeo-Designer variable or another object directly in the script. Use methods to interact with Vijeo-Designer objects.

  • Void type is used only as a function return type. One of the expressions has evaluated into a void value and cannot be processed, which could indicate you've added a parameter to a method that does not take any parameters.

  • Conversion from type "" to type "" may lose data. A value is being assigned to a variable where the data types don't match. In some cases this operation is acceptable; however, this time it may result in a loss of data. If you want to continue with this assign operation, typecast the value.

Example:

int a = 0;

double b = 0.0;

a = b;      // Fails at validation

a = (int)b; // Typecast to succeed
