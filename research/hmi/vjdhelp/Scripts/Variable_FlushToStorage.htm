flushToStorage

Function

When a variable is associated with a data logging group, you can use flushToStorage to move the variable's data from the memory buffer to permanent storage.

The buffer size is configurable. You can set the buffer size in the No. of Records in RAM property in the Logging Group property inspector. When the buffer becomes full, variable records are moved from the buffer to storage, so new variable records can be added to the buffer.

You may want to run flushToStorage:

  • At defined intervals (Application Script: Periodic)

  • When you change panels (Panel Script: On Close)

  • When you perform maintenance

  • When you are going to change storage location (CF Card/SD Card or USB drive)

  • This method transfers a single variable's data to storage. This method does not transfer the entire buffer containing all the historical data of all the variables to storage.

  • When you depend on automatic flushing of buffer data to storage, all data may not be removed from the buffer. Use flushToStorage to make sure all the data is moved from the buffer to storage.

  • Data in the SRAM can only be flushed once and cannot be flushed again. If you use the Copy to USB function and choose to delete the files from the source after copying, no new files are created unless there is new data in the SRAM.

Format

boolean VariableName.flushToStorage();

Return Value

Returns true when historical data in the buffer is successfully moved to the electronic file in the Secondary Drive or Optional Drive.

Returns false when the variable does not store its history. In other words, the variable is not associated with a data logging group.
