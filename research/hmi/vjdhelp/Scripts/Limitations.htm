18.3.4 Key Points

Keep in mind the following key points when writing scripts:

 

Dangerous Situations

  • Do not use scripts in applications that may affect human life or in other scenarios that may be considered dangerous.

 

String, StringBuffer, and Java Primitive Arrays

  • Do not create String or StringBuffer objects or Java primitive arrays that occupy huge amounts of space in memory. For example, if you write the following script, a lot of space in memory will become occupied and could cause Vijeo-Designer Runtime to halt operations.

int a[] = new int[30000]; // Occupies 120K in memory

 

Accessing elements in Arrays

  • Avoid indirectly accessing elements in Vijeo Designer array variables.

int a = 10;

Array01[a].getIntValue(); // Avoid indirect array elements

                          // This call loads into memory the entire

                          // Vijeo-Designer variable array

 

When indirectly accessing elements in Vijeo-Designer array variables, the entire array is loaded into memory. If the array is very large (e.g. 1000 elements), the array will occupy huge amounts of memory and force the target machine to slow down.

To avoid this memory problem, use a constant to define the array element.

Array01[10].getIntValue();// Constant value for array element

A total of 3 threads are created at runtime.

1. Action01 and Action02 run in the same thread because their Frequency and Scheduling are the same.
2. Action03 runs in a separate thread because its Scheduling is different from scripts in Thread 1, and Frequency is different from scripts in Thread 3.
3. Action04 and Action05 run in the same thread because their Frequency and Scheduling are the same.

  • When multiple actions  run in the same thread, a delay in one can cause a delay in others.

  • When using scripts in actions, be careful to not set a trigger type that makes the script run repeatedly like an infinite loop. For example, a script that is triggered to run immediately after it executes may cause some target machines to stop responding.

 

Loops

  • When using loops (do-while, for, while), do not create infinite loops. Infinite loops cannot be caught at validation and cause the target machine to crash or stop responding as more and more memory is used by the script.

  • When using loops (do-while, for, while), and the script takes too long to complete, the system will abruptly terminate the script. Touch type scripts, such as Touch animation and Touch Action scripts, terminate after two seconds. Event type scripts, such as On Startup and Conditional scripts, terminate after five seconds.

 

NULL Return Values

  • Some Vijeo Designer script methods and Java methods may return NULL. You must account for this possibility. In your scripts, include code to check your return values for NULL and to account for NULL return values.

 

Java Language Compatibility with Vijeo Designer Scripts

  • The Vijeo-Designer scripting language is based on Java™. As a result, you cannot use Java keywords as object or script names. Other Java syntax rules also apply.

  • The Vijeo-Designer scripting language is case-sensitive. This includes: Vijeo-Designer object names, variable names, method calls, keywords, and so on. That means Int01 is not the same as int01. And Int01.getIntValue() is not the same as Int01.getintvalue().

    • When working with decimal numbers, type 0.1234 (not .1234).

    • When working with decimal numbers, type a period [ . ] to denote a decimal point 0.1234. Other methods of denoting the decimal point, such as the comma [ , ] used in many European countries, are not accepted. In other words, the value 0,1234 will not pass validation.

    • Local script variables must be initialized before they're used in the script, especially when used in a comparison. Even if the variable is assumed to be 0, you must assign a 0 value to the variable before it can be used, otherwise building of the user application may fail.

integer a, b=0; // a is not initialized

if ( a==0 )     // cannot build

if ( b==0 )     // build successful

    • Semi-colons mark the end of statements. Enclose expressions in parentheses.

    • Assigning values from one data type to another may cause loss of data. Vijeo-Designer scripts will prevent you from doing this unless you typecast the values.

int c = 0; double d = 0.0;

c = d;      // will not validate

c = (int)d; // validate successful

 

In scripts, fractional values are of type double. As a result, if you are using floats, typecast fractional values assigned to a float.

float a = 0.0;        // will not validate

float b = (float)0.0; // validate successful

  • Fractional values in scripts support double precision; Vijeo-Designer variables support single precision. When writing a double to a Vijeo-Designer REAL variable, behind the scenes the script typecasts the value to a float, which may cause loss of data and precision.

double d = Math.sin(90);

Float01.write( d );

// d is typecasted

// REAL01.write( float(d) );

  • The maximum size of Java objects is 64KB. As a result, huge scripts (such as 1000+ lines) overflow the stack and cause the application to fail.
