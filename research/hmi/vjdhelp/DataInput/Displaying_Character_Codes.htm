11.6.2 Displaying Text with Character Codes

When the equipment uses character codes to store text, you can display the correct set of characters by converting the character codes (ASCII, Unicode, or ANSI) from the device addresses so they display correctly.

In Vijeo-Designer, to display text converted using character codes, first define the variable's data type for the device address as String, and then use Value animation or a String Display part to display the text. This section shows you how to display text using a String Display.

  1. In the device driver properties, select the String Encoding as ASCII, Unicode, ANSI.

  1. For the variable, select String in the DataType field. In the DeviceAddress field, specify the starting address of the equipment that stores the string code to the DeviceAddress field.

  1. Click the Data Display icon on the Graphical Objects Parts toolbar, and select String Display from the list.

  1. On the panel, click and draw the area where you want the string display.

The String Display Settings dialog box opens.

  1. In the General tab, set the following properties:

  2. Variable: Specify the String variable that will access and input the display data

  3. Display Length: Available only when Data Type is String. Select lengths of the String, from 1 to 100.

  • Set the Display Length below the value set in the NumOfBytes field when a variable is created. If the value is larger than the NumOfBytes, the text cannot be displayed.

  1. Define the label settings, such as the language and font properties for the text.

When ASCII or ANSI is selected in the driver's String Encoding property, the range of codes depends on the font type.

Font Type

String Code Range

Western

00~FF

Japanese

00~7F

Others

  1. In the Color tab, set up the color properties for the text.

  1. Click OK.
    For details, see Section 11.2, Data Display Settings.

  2. Start Runtime.
    The target displays the character codes stored in the defined device addresses. The text is updated when the character codes in the device addresses change.

  • You can display multiple lines of text by using a carriage return code (CR:0x000D or LF:0x000A).

  • If you input more text than can be stored in the corresponding string variable (as defined in its NumOfBytes property), the input will be truncated.

  • If the text in Value animation appears partially cut off, adjust the size of the object, font, or font size.

  • If the number of characters you want to display is less than the Display Length defined in Value animation, store NULL (0x00) in all excess addresses.

Example:

Value Animation Display Length: 6

Actual Display: ERROR (5 characters)

On the PLC, use NULL termination when storing strings. For ASCII, ANSI, and Shift-JIS, NULL is 0x00. For Unicode, NULL is 0x0000

  • When using a String variable with an external data source, the number of characters in the variable properties and the Display Length in Value animation is different. Equipment strings calculate data length using bytes. In Value animation, when you define the Display Length, it does not differentiate 2-byte and 1-byte characters. Although you can set up and type up to 100 characters into the Value animation, the equipment can only store 100 1-byte or 50 2-byte characters.

  • When using String variables, the order of the character codes (Low-High or High-Low) depends on the equipment used.
    In the following example, the text does not display as intended.

In this case, the equipment is one that stores the characters in High-Low order, and when the device driver flips the codes to read the String variable, the characters display on the target machine in Low-High order.

If Runtime does not display the text correctly, you need to store the character codes in the correct order on the equipment side. If the text still does not display as intended, make sure you selected the correct String encoding format.
For more information about the High or Low order of devices, see the corresponding equipment driver manual section titled Supported Device Addresses.
